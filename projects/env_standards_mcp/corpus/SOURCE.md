# 语料来源与抽取口径

这份文档回答三个问题：**数据从哪来、怎么抽的、哪些地方动过手**。
任何人想改 `gb36600_limits.json`，先读这里。

## 1. 源

**GB 36600-2018《土壤环境质量 建设用地土壤污染风险管控标准（试行）》**

- 批准 2018-05-17，发布 2018-06-22，实施 2018-08-01
- 本机文件：`_local/standards/GB36600-2018.pdf`（原版，扫描件）与
  `_local/standards/GB36600-2018-textlayer.pdf`（带 text layer 的版本，解析用这个）
- **PDF 不进仓库**（ADR-0020），只提交解析后的 `gb36600_limits.json`

| 内容 | PDF 页 | 印刷页 |

| 3 术语和定义（3.6 土壤环境背景值） | 4 | 1 |
| 4 建设用地分类（4.1.1 / 4.1.2 两类用地） | 6 | 3 |
| 表 1 基本项目（45 项）起 | 6 | 3 |
| 表 1 续 + 表 2 其他项目（40 项）起 | 7 | 4 |
| 表 2 续 | 8 | 5 |

| 附录 A 砷 / 钴 / 钒 的土壤环境背景值 | 17 | 14 |

## 3. 抽取口径

两种提取模式交叉验证，缺一不可：

| 模式 | pypdf 调用 | 用来干什么 |
|---|---|---|
| 行序模式 | `extract_text()` | 切「哪几个数属于哪一项」——表格在 PDF 里换行位置不固定，序号、名称、CAS、四个数常各占一行 |
| 列位模式 | `extract_text(extraction_mode='layout')` | 核「这个数落在哪一列」——行序模式可能把相邻两行的数串起来 |

**核验规则**：每个条目的四个原始数值字符串（按 PDF 里的写法，比如 `3.0`、`1×10-4`）
必须能在列位模式里按顺序匹配上（允许数值后面跟一个上标注 `①`）。核不上的条目进
`cross_check.failed` 列表，**不让错位的数字悄悄进 JSON**。当前 `failed` 为空。

数值保留 PDF 里的原始写法在 `raw` 字段里，核对原文时按 `raw` 比，不要按 `screening` /
`control` 里的浮点数比（`3.0` 会被 `float()` 变成 `3.0` 而不是 `3`，反过来也成立）。

## 4. 动过手的地方

只有一处：`表 1 第 42 项` 的名字。

标准原文这一项是 **芴**（CAS 218-01-9，荧蒽系列：苯并[a]蒽、苯并[a]芘、苯并[b]荧蒽、
苯并[k]荧蒽、**芴**、二苯并[a,h]蒽、茚并[1,2,3-cd]芘、萘，顺序能对上）。
但官方 PDF 内嵌字体的字形映射有问题，text layer 里取出来是 `䓛`（U+44DB）。

处理方式：`build_corpus.py` 里 `NAME_FIXES` 按 **CAS 号** 校正，并且只在
「解析出来的名字正好是 `䓛` 且 CAS 命中 218-01-9」时才改，条件不满足就不改，
不会误伤别的条目。原始字形保留在条目的 `name_raw` 字段里。

## 5. 附录 A 的特殊处理

附录 A 的三张表（砷 A.1、钴 A.2、钒 A.3）形状跟表 1 / 表 2 完全不同：
一列土壤类型（顿号分隔，**可能跨行断开**）+ 一列数值。

跨行断词是这个表最大的坑。原文里 `灰漠土、灰` 结尾一行，下一行开头是 `棕漠土、...`，
按行切就会切出一个不存在的土壤类型「灰」。所以 `parse_background()` 先把行拼成整段文本，
再按顿号切，不按行切。

附录 A 只给了**砷、钒、钴**三个元素的背景值。其余元素（镉、铅等）的背景值按 3.6
由本地块自行确定，标准里没有，**服务不会编一个出来**。

## 6. 复核方法

```bash
# 从仓库根跑，PDF 路径由调用方给
python -I projects/env_standards_mcp/corpus/build_corpus.py \
    _local/standards/GB36600-2018-textlayer.pdf \
    -o projects/env_standards_mcp/corpus/gb36600_limits.json

# 逐字节比对（JSON 是提交进仓库的基线，改了就必须重跑生成器）
git diff --stat projects/env_standards_mcp/corpus/gb36600_limits.json
```

`-I` 是必须的：解释器会从脚本所在目录和当前目录加载模块，下载来的 PDF 旁边
如果有一份 `json.py`，`import json` 就会跑到它。

跑完应该看到：`items 85 t1 45 t2 40` 与 `unverified (cross-check failed) 0`。
