# 新项目开工清单

给**下一个**项目用。已经定稿的三个主项目不走这套流程（它们零改动，见 ADR-0010）。
新项目从第一天就按这份清单走，比事后补要省得多。

每一步都给了**完成判据**——判据不过就是没做完，不靠感觉往下走。

---

## 0. 拷问需求：先把问题问清楚再写第一行代码

- **做什么**：把想法丢给 `/mattpocock-skills:grill-with-docs`，让 agent 扮演挑剔的提问者，
  逼自己回答「用户是谁」「输入长什么样」「输出怎么验收」「失败了怎么办」
  「为什么不能用现成的」「哪些部分必须是 AI、哪些必须是确定性代码」。
  它会边问边落 ADR 和术语，落点与格式按 `docs/agents/issue-tracker.md` 那张偏差表，
  不按 skill 默认值。
- **后续两步**：`/mattpocock-skills:to-spec` 把对话合成 spec，
  `/mattpocock-skills:to-tickets` 拆成一条条带 `Blocked by` 的 ticket；
  落点见 `docs/agents/issue-tracker.md`。
- **完成判据**：能用一句话说清「谁在什么场景下用它，输出一份什么东西，
  拿什么判断它做对了」。说不出这句话就是还没想清楚。
- **坑**：先写代码再想需求，返工成本是前期想需求的三倍以上。

## 1. 定位：这个词属于哪个 context

- **做什么**：打开 `GLOSSARY-MAP.md`，找到新项目落在哪个 context 下。
  已有词必须用表里的写法；表里没有的词，先加进对应 context 的术语表，再写代码和文档。
  一个词在两张表里出现就是分叉，必须合并到一处。
- **完成判据**：新项目用到的每个专有名词，都能在某张 `GLOSSARY-*.md` 里查到。
- **坑**：术语表不是词典，只收「本仓怎么用这个词」。

## 2. 立决策：会改变后续动作的选择，写成 ADR

- **做什么**：凡是「选了 A 就回不去选 B」的决定，写一条 ADR 到 `docs/adr/`，
  格式是「约束 → 裁定 → 后果」，并在 `docs/adr/README.md` 加一行。
  典型例子：默认检索模式用哪档、模型存不存权重、数据从哪来、要不要离线兜底。
- **完成判据**：`docs/adr/README.md` 里能查到新项目的关键选择，且每条都有编号。
- **坑**：不要把「做了什么」写成 ADR（「用了 LangChain」），要写「为什么这么选、
  代价是什么」。

## 3. 定接口：先写清楚别人怎么用它

- **做什么**：把对外接口定下来（函数签名、CLI 参数、输入输出格式），
  写进项目的 `CLAUDE.md`。里面只写 agent 进目录就需要知道的东西：
  怎么跑、目录各管什么、哪些数字不能动。
- **完成判据**：一个新会话的 agent 只读 `CLAUDE.md` 就能跑起项目并知道
  「哪些东西不能碰」。
- **参考本仓已有的两个**：`projects/env_agent/CLAUDE.md`（Agent 编排怎么跑、
  12 条用例在哪、已知限制）和 `projects/lora_finetune/CLAUDE.md`
  （数据从哪来、目录各管什么、两个对外数字 29.4% / 91.2% 怎么算的）。
- **坑**：`CLAUDE.md` 被 gitignore，所以它是本机工作约定；
  要给别人看的东西（README、术语表、ADR、测试）另找公开落点。

## 4. 搭反馈闭环：一条命令能告诉你对不对

- **做什么**：给项目配一个入口命令，输出一眼能看的账（几行几列、几个对几个错）。
  反馈越快越好：先写一个 10 秒内能跑完的冒烟检查，再上完整评测。
  依赖外部服务（API key、GPU）的用例一律 **skip 而不是 fail**，
  并在输出里写明「因为缺 key 跳过」。
- **完成判据**：一条命令跑完，输出里有明确的通过/失败数，退出码非零即失败。
- **本仓怎么做的**（照抄这个形状）：`projects/evals/run_all.py` 是入口，
  `tools/check_all.py` 是全仓静态检查入口（退出码 = FAIL 项数），
  `projects/evals/tests/` 是契约测试的位置。**新项目照这个形状建，不要另起一套。**
- **坑**：别用「跑通了没报错」当通过判据，要对**具体数字**做断言。

## 5. 造数据与标签：先确认标注口径

- **做什么**：写评测集时先定好 id 规则、字段必填项、类别分布。
  评测集本身要有测试（条数、id 唯一、字段非空、分布符合预期）。
- **完成判据**：`eval_set.jsonl` 有一条测试守着，改了条数会红。
- **坑**：同一份数据有「30 条」「23 条」「分母 20」三层说法时，
  在术语表里把三层关系写清楚，不要让记忆去扛。

## 6. 写代码：守住本仓的接口约定

- **做什么**：按 `CLAUDE.md` 的「ML API 约定」写模型类（`fit` / `predict` /
  `predict_proba` / `sample` 的形状和返回类型固定），随机种子 `random_state=42`，
  线性模型 `lr=0.01, epochs=1000`。新增模型走 Registry Pattern：
  写类 + 在 `ALGORITHMS` 登记，不改路由。控制台 `print()` 只用 ASCII，
  中文和符号留给 matplotlib。
- **完成判据**：新模型能通过路由被调起来，输出形状符合约定。
- **坑**：Windows 控制台是 GBK，`print()` 里出现 `²` `×` `−` 会直接抛
  `UnicodeEncodeError`。

## 7. 留数字的口径：每个数字标来源

- **做什么**：脚本里的每个参数标来源 `[S]` 标准 / `[L]` 文献 / `[E]` 估算 /
  `[C]` 计算 / `[A]` 假设。文章里的每个数字要能回源核，**没有官方源就不放**。
- **完成判据**：拿任何一个数字都能说出它从哪来，或者它明确标着是估算。
- **坑**：估算值不能进对外文章。宁可删段，不要用「据估计」糊过去。

## 8. 留产物：生成器 + 归档基线

- **做什么**：图和 CSV 一律由 `scripts/<series>/gen_*.py` 生成，不手工改产物。
  生成完把产物提交到仓库，重跑一次必须逐字节一致
  （`cd <产物仓> && git status --porcelain` 为空）。
- **完成判据**：重跑生成器后产物仓工作区干净。
- **坑**：改数字要改生成器或模型，不要改 PNG。归档基线一破，复现能力就没了。

## 9. 收尾：登记与交接

- **做什么**：更新 `_local/plan.md`（进度、待写清单、变更记录）、
  根 `README.md`（对外索引）、需要的话写 `_local/article_notes/<series>/NN_notes.md`。
  会话要换人/换仓库时，写 handoff：阶段 / 已完成 / 未完成 / 关键数字口径 /
  下一步第一步 / 已知坑（模板见 `docs/superpowers/plans/_meta/review-protocol.md`）。
  设计文档落在 `docs/superpowers/specs/<topic>/`，实施产物落在
  `docs/superpowers/plans/<topic>/`，这两个目录不公开。
- **完成判据**：关掉所有窗口后，只看 `README.md` + `_local/plan.md` 的人
  能接上下一轮。
- **坑**：三份文件（README / CLAUDE.md / plan.md）不互抄正文，交叉引用只写路径。

## 一页速查

| 阶段 | 一句话 | 完成判据 |
|---|---|---|
| 0 拷问 | 先问清楚要解决什么 | 一句话说清用户、场景、产出、验收 |
| 1 术语 | 用词查表，表里没有就加表 | 每个专有名词都能查到 |
| 2 决策 | 会回不去的选择写 ADR | ADR 索引表里有条目 |
| 3 接口 | 写好项目自己的 CLAUDE.md | 新 agent 只读它就能跑 |
| 4 闭环 | 一条命令出账 | 有明确的通过/失败数 |
| 5 数据 | 先定标注口径 | 评测集有测试守着 |
| 6 代码 | 守住接口约定 | 路由能调起来 |
| 7 数字 | 每个数字标来源 | 随便抽一个能回源 |
| 8 产物 | 生成器产出 + 逐字节可复现 | 重跑后产物仓干净 |
| 9 收尾 | 登记 + 交接 | 别人能接上下一轮 |
