# ADR-0023 · plan.md 是索引层，细节分流到 notes / ADR / plans

- 状态: accepted
- 登记日期: 2026-11-07

## 约束

`_local/plan.md` 同时当状态快照、历史档案和项目文档用。2026-11-07 实测
418 行 / 82,044 字符：

- 变更记录一节占 61%（55 行 / 50,029 字符，最长一条 2,216 字符）
- 标题块 11 行（其中 8 条「最近一次更新」摘要，6,391 字符）与变更记录表重复，
  同期事件记两遍
- 已发文章标题列表与 `README.md` 重复
- 副线项目段落（16,003 字符）是项目 README、`docs/superpowers/`、`_local/job/`
  的摘要

同一件事记两遍，改一处忘另一处，结果是三处说法不一致。每次 Edit plan.md
还要先读完整个文件才能改一行，这个成本每轮都在付。

## 裁定

plan.md 降为「状态 + 索引」两层：

| 层 | 内容 | 约束 |
|---|---|---|
| 状态 | 还差几篇、哪个项目卡在哪 | 直接写正文 |
| 索引 | 发生过什么 | 每条 ≤200 字符 + 指向细节落点 |

细节分流到固定落点，同一件事只在一处维护：

| 内容 | 落点 |
|---|---|
| 文章论证线 / 数据 / 坑 / 引用 | `_local/article_notes/<series>/NN_notes.md` |
| 决策与理由 | `docs/adr/` |
| review 过程与修复 | `docs/superpowers/plans/<topic>/` |
| 项目怎么跑 / 怎么走到今天 | `projects/*/README.md`、`projects/*/CLAUDE.md` |
| 方法论与踩坑 | `docs/superpowers/plans/_meta/` |
| 求职材料 | `_local/job/` |
| 已发文章清单 | `README.md` |

CLAUDE.md 不作为细节落点：它的静态前缀每轮重读（本机实测 32,079 token），
放大它等于放大每轮成本。它只留「记录落点」这个小节本身。

`tools/check_all.py` 的 `check_plan()` 守上限：plan.md 总长 ≤ 30,000 字符、
变更记录单行 ≤ 200 字符。缺文件判 SKIP（`_local/` 是本机私有目录，换机器
就没有这个文件），跟 `check_memory()` 同一个套路。

## 后果

plan.md 只剩「现在到哪了」和「发生过什么 + 去哪看」，读它不用读它引用的东西。

写 plan.md 之前先问一句：这事该落在上面哪一格。落不进去的，要么不值得记，
要么该写成 ADR（是决策），要么该写成 notes（是文章级知识）。

ADR-0009 不推翻：plan.md 仍然管进度、待写清单、变更记录三样，只是变更记录
从正文变索引。
