# ADR-0020 · 标准原文 PDF 不进仓库，提交解析后的 JSON 基线

- 状态: accepted
- 登记日期: 2026-11-04
- 决策日期: 2026-11-04

## 约束

`projects/env_standards_mcp/` 的语料来自 GB 36600-2018 的官方 PDF（本机
`_local/standards/GB36600-2018-textlayer.pdf`）。

三个约束：

1. **PDF 是国标原文**，公开出版物，但不是本仓的作品，仓库要上传 GitHub。
2. **PDF 没有 text layer 就没法解析**。官方原版是扫描件，本机另外准备了一份带
   text layer 的版本（`_local/standards/GB36600-2018-textlayer.pdf`），
   这份**不是官方渠道下载的**，不能指望别人也有。
3. **但纯运行时数据（JSON）必须能直接跑**。clone 下来的人不该先去找 PDF。

同时，扫描 / OCR 出来的表格有个固有风险：**数字错位**。一行读串到下一行，
某个项目的筛选值就可能变成管制值，而这种错在 JSON 里完全看不出来。

## 裁定

**PDF 不进仓库，仓库里是解析后的 JSON 基线；解析过程可复核，数字对不上的不许进 JSON。**

- 提交 `corpus/gb36600_limits.json`（解析产物，即基线）与 `corpus/build_corpus.py`（生成器）。
  改了数字要改生成器，不改 JSON。
- **两种提取模式交叉核验**：`extract_text()` 取行序定归属，`extract_text(mode='layout')`
  取列位定列位。每个条目的四个原始数值字符串必须能在列位模式里按顺序匹配上
  （允许数值后跟一个上标注）。核不上的条目进 `cross_check.failed` 列表，**留在 JSON 里等人看，
  不悄悄丢弃也不悄悄放过**。
- 抽取口径、页码映射、动过手的地方全部写进 `corpus/SOURCE.md`：
  - 页码映射：表 1 起于 PDF 第 6 页（印刷页 3），附录 A 在 PDF 第 17 页（印刷页 14）
  - 动过手的地方只有一处：表 1 第 42 项的标准 PDF 字体把「芴」映射成 `䓛`（U+44DB），
    按 CAS 218-01-9 校正，原始字形保留在条目的 `name_raw` 字段
- 重建语料时 Python 必须带 `-I`：解释器会从脚本目录和当前目录加载模块，
  下载来的文件旁边有一份 `json.py`，`import json` 就跑到它。

## 后果

- clone 下来就能跑服务与评测，不需要 PDF；只有重建语料才需要自己准备 PDF。
- 每一个限值都能回到「哪一页、哪个字形、怎么抽的」，复核有入口。
- **换机器重建语料需要自己找 PDF**，本机那份 text layer 版不是官方渠道产物。
- 解析器本身是代码，会有 bug。所以有 `tests/test_corpus.py` 守条数（85 = 45 + 40）、
  四个值齐不齐、交叉核验是否干净，`eval/run_eval.py` 里还有一层语料自检。
- 版权上不做判断：国标原文是公开出版物，但仓库上传的是自己解析的数据文件，
  不含原文 PDF。
