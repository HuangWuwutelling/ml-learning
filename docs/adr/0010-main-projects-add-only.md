# ADR-0010 · 主项目零改动

- 状态: accepted
- 登记日期: 2026-11-01
- 决策日期: 2026-11-01
- 修订: 2026-11-02，措辞从「只加测试与脚本」收紧为「零改动」，测试外置见 [ADR-0015](0015-contract-tests-live-outside-frozen-projects.md)

## 约束

`环境法律法规智能问答系统/`、`projects/env_agent/`、`projects/lora_finetune/`
是简历上的三个主项目，会被面试追问。改动越多，风险越高。

`环境法律法规智能问答系统/` 还有第二重约束：GitHub 上那份 `env-law-qa` 是这个目录的
**手工同步镜像**，主仓加一批文件，镜像就得跟一次，跟不上就会出现「本地有、
GitHub 没有」。

## 裁定

**这三个项目目录里一个字节都不改**：不加测试、不加脚本、不改业务代码、
不改最终数字、不改 prompt、不改工具编排。确实需要改业务逻辑时，
先单独立项讨论，不在本轮顺手做。

需要在主项目上做检查时，检查代码写到项目外面去（见 ADR-0015）。

## 后果

反馈闭环只能建在可观测的边界上：评测集结构、产物结构、公开接口。
因此这里的测试是**元测试**为主，不是业务回归测试。这不是偷懒，
是这条约束下的必然形态，写简历和面试时要照实说。
术语对应 [GLOSSARY-engineering-process.md](../../GLOSSARY-engineering-process.md) 的
「边界测试」与「元测试」。

好处是镜像不再需要为测试文件同步一次，`env-law-qa` 与主仓的差异只可能是
「主仓有新东西」，不会是「两边文件列表不一样」。
