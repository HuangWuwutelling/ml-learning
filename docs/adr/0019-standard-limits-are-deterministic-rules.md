# ADR-0019 · 标准限值与风险分档走确定性规则，不交给模型

- 状态: accepted
- 登记日期: 2026-11-04
- 决策日期: 2026-11-04

## 约束

`projects/env_standards_mcp/` 要给 AI agent 提供 GB 36600-2018 的筛选值、管制值，
以及一个测值该落到哪一档。

现实约束有三条：

1. **答案唯一**。某污染物在某类用地下的筛选值是多少、某测值超没超筛选值，
   标准原文里写死了，没有发挥空间。
2. **结论要能被指回条款**。给第三方看的筛查结论要写「依据 GB 36600-2018 第 5.3.4 条」，
   模型生成的数字没法复核，出了事追不到出处。
3. **模型答标准限值经常给错数**。GB 36600 有 85 个项目、每项四个数，
   让模型凭记忆填必然出错，而错一个数就可能把「要修复」说成「可忽略」。

但把规则全写死在代码里也有代价：标准会改版本，用地分类和条款结构都不是简单的查表。

## 裁定

**凡是答案唯一的判定，一律写成确定性规则，模型不进 server。**

- 限值、条款号、边界比较（「等于筛选值算哪一档」）全部落在 `server/rules.py` 的规则里，
  每条规则在文件头标了对应的条款号。
- **边界归上一档**：测值等于筛选值走 5.3.2（可忽略），等于管制值走 5.3.4（做风险评估），
  两头都按标准原文的「等于或者低于 / 等于或者低于」措辞取。
- 注① 的豁免（超筛选值但不超本地块背景值，不纳入污染地块管理）是一个显式的例外分支，
  成立时**同时保留没豁免时的档位**，不覆盖掉。
- 认不出来的输入（用地类型说不清、污染物不在表 1 / 表 2）**报错，不猜**。
  用地类型认错会整套限值用错列，这个代价比回问一句大。
- 模型只留在 server 外面：把用户的自然语言问题变成工具参数、把结论讲成人话。

## 后果

- 每条结论都能追到条款号，判定逻辑能被单测逐条覆盖（`tests/test_rules.py`，边界值各测一次）。
- 加一本标准不用改判定框架：每本标准一份语料 JSON + 一套规则。
- **代价是标准一改就要改规则**。GB 36600 的条款结构（5.3.x）不是所有标准都一样，
  换个标准可能连档数都不一样，那时得为新标准单开一套规则，而不是硬套。
- 覆盖率有限：本仓只接了 GB 36600-2018 一本标准、85 个污染物项目。
