# ADR-0015 · 契约测试放在冻结项目外面

- 状态: accepted
- 登记日期: 2026-11-02
- 决策日期: 2026-11-02

## 约束

[ADR-0010](0010-main-projects-add-only.md) 把三个简历主项目定为「零改动」。
但反馈闭环要落在能观测的地方才有用：评测集有几条、id 怎么排、默认档位是哪个、
README 上的数字和产物对不对得上。这些东西全在三个主项目目录里。

原先的想法是「只加测试」：`环境法律法规智能问答系统/tests/`、
`projects/env_agent/tests/`、`projects/lora_finetune/tests/`。
问题有三个：

1. `环境法律法规智能问答系统/` 在 GitHub 上是**手工同步的镜像**（`env-law-qa`），
   在它目录里加文件，主仓和镜像的文件列表就分叉了，要手工再同步一次。
2. 「只加不改」是个会自我磨掉的边界：先加测试文件是加，第二次改测试里的断言
   就是在改项目的事实了。目录分开，边界才守得住。
3. `.gitignore` 里根级 `tests/` 规则默认排除所有测试目录，
   `环境法律法规智能问答系统/tests/` 要上 GitHub还得单开一条例外，
   每多一个项目就多一条例外，例外本身也是要维护的东西。

## 裁定

**契约测试外置到 `projects/evals/tests/`，三个主项目目录零改动，
`.gitignore` 一行不改。**

- `projects/evals/tests/` 命中已有的 `!projects/*/tests/` 例外，直接上 GitHub。
- 契约测试只**读**主项目的产物与源码，不 import 业务代码：
  配置默认值用正则从源码取 `os.getenv(NAME, "default")` 的默认字面量，
  用例表用 `ast` 解析，产物直接读 JSON。唯一执行真业务代码的是纯函数 `rrf_fuse`。
- 入口是 `python projects/evals/run_all.py`，也挂进 `tools/check_all.py` 的
  `rag` / `agent` / `lora` 三项。

## 后果

- 三个主项目目录保持可逐字节比对，`env-law-qa` 镜像不需要为测试同步。
- 契约测试验的是**口径**（默认档位、条数、id、工具清单、README 数字），
  验不了**智能**（模型答得好不好）。模型质量仍由各自的评测脚本负责，
  跑不动时不要拿契约测试冒充评测结果。
- 想给某个主项目加真正的回归测试，得先推翻 ADR-0010，不是这里能顺手做的事。
- 新项目没有历史包袱，不必套这条外置规则；这条只约束三个已冻结的项目。
